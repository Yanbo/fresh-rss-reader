## 2. 项目约束

### 2.1 边界约束

- **不对父项目 EAF 作任何改动**：fresh-rss-reader 的开发仅限于本项目的文件和代码
- **任何改动都不能发生在 EAF 中**：所有实现都在 fresh-rss-reader 目录内完成，不修改 EAF 核心文件或其他应用程序文件
- **依赖 EAF 接口**：通过 EAF 提供的公开接口（如 Buffer 体系、QWebChannel 等）进行集成，但不修改接口本身

### 2.2 技术约束

- **前端框架**：Vue 3 + Composition API
- **构建工具**：Vite
- **运行环境**：EAF 框架（QWebEngine + QWebChannel）
- **Python 后端**：使用 EAF 的 Buffer 体系
- **主题适配**：从 Emacs 主题获取颜色/字体设置

### 2.3 兼容性约束

- **Doom Emacs 兼容性**：
  - 模块加载方式与 Doom Emacs 插件加载模式兼容
  - 键绑定设计避免与 Doom Evil 键绑定冲突
  - 配置组织方式能接入 Doom Emacs 的配置方式
  - 主题、字体等 Emacs 环境设置与 Doom 视觉风格一致

## 3. 实现阶段

### 3.1 阶段 1：工程初始化和前端骨架

**目标**：建立可运行的前端工程，搭好组件树和通信/状态的壳

**主要事项**：
- 用 Vite 初始化 Vue 3 项目
- 确定 `src/` 下的主要模块位置
- 配好构建输出结构，让 Python 侧能加载前端产物

**验收行为**：
- 本地 serve 后能打开页面
- 页面上能看到根布局/占位结构
- `services/qweb.js` 有 QWebChannel 初始化结构

### 3.2 阶段 2：视图组件和基本数据流

**目标**：实现 feed 列表、文章列表、文章详情三个主要视图

**主要事项**：
- 实现 `FeedList.vue`、`ArticleList.vue`、`ArticleView.vue`
- 在 `useAppState.js` 中定义状态和切换函数
- 在 `App.vue` 中根据状态控制区域显隐

**验收行为**：
- feed 列表和文章列表能呈现
- 选中 feed 后文章列表变化
- 选中文章后详情展示
- 全屏切换和返回列表在前端模型上能走通

### 3.3 阶段 3：阅读流和返回路径

**目标**：确立"打开文章 -> 全屏/inline -> 快捷键返回列表"核心交互流

**主要事项**：
- 实现打开文章的命令
- 实现返回列表的命令
- 快捷键 `q` 绑定到返回逻辑
- 全屏切换命令或行为
- 文章已读标记在阅读流中的位置

**验收行为**：
- 按下打开文章命令后，文章内容可见
- 在全屏或 inline 详情状态下，按返回命令后能回到列表视角
- 返回命令基于应用状态，不依赖窗口位置

### 3.4 阶段 4：feed 刷新、状态存储和数据持久化

**目标**：让 feed 数据能读取、刷新、保存

**主要事项**：
- feed 刷新实现（抓取和解析线程）
- 状态存储（feed 列表、文章列表、已读状态）
- 保存/加载逻辑

**验收行为**：
- feed 刷新后文章列表会更新
- 已读标记能落地
- 刷新/重载后，列表和选中状态不丢失或不错乱

### 3.5 阶段 5：OPML 和周边管理功能

**目标**：完成标准的导入/导出能力和部分管理命令

**主要事项**：
- OPML 导入
- OPML 导出
- 添加/移除 feed 等管理命令的完善

**验收行为**：
- 从 OPML 文件导入后 feed 列表正确增加
- 导出能得到结构合理的 OPML 文件
- 添加/移除 feed 后列表和状态跟着更新

### 3.6 阶段 6：主题适配、健壮性和兼容性收尾

**目标**：让前端视觉/配色随 Emacs 主题变化，处理常见边界情况

**主要事项**：
- 从 Python/Emacs 获取主题信息并传递给前端
- 前端根据主题模式调整基础样式
- 常见边界情况处理
- 键绑定与 Doom Emacs 的兼容性检查

**验收行为**：
- 在不同主题设定下，应用的基础色彩/对比合理
- 空列表、空文章、缺失链接等情况下不出现明显破损或卡死
- 常用快捷键在 Doom Emacs 下可用且不严重冲突

- 文章已读/未读状态展示

### 4.3 文章内容阅读

- 打开文章链接进行阅读
- 文章内容展示

### 4.4 已读标记

- 标记文章为已读
- 已读状态在文章列表中展示

### 4.5 OPML 导入/导出

- 从 OPML 文件导入 feed 列表
- 将当前 feed 列表导出为 OPML 文件

## 5. 交互模型

### 5.1 布局方式

- **列表 + 详情同章**：复合布局，列表和详情在同一个主视图内
- **允许全屏详情**：文章可以全屏显示，方便专注阅读
- **快捷键返回**：通过快捷键返回列表，这是主要返回手段

### 5.2 视图切换逻辑

```
+------------------+------------------+
|                  |                  |
|    Feed List     |   Article List   |
|                  |                  |
|                  +------------------+
|                  |                  |
|                  |   Article View   |
|                  |   (inline)       |
|                  |                  |
+------------------+------------------+

或者全屏模式：

+----------------------------------+
|                                  |
|         Article View             |
|         (fullscreen)             |
|                                  |
+----------------------------------+
```

### 5.3 返回路径设计

- **`q`**：主要返回命令，从全屏/详情返回列表
- **设计意图**：任何时候按 `q` 都应该能清楚地回到 feed/news list
- **实现方式**：基于应用状态，而不是窗口位置

## 6. 快捷键设计

| 快捷键 | 方法 | 说明 |
|--------|------|------|
| `f` | `open_article` | 打开当前文章 |
| `q` | `close_article` | 返回列表（主要返回命令） |
| `j` | `next_article` | 下一篇文章 |
| `k` | `prev_article` | 上一篇文章 |
| `n` | `next_feed` | 下一个 feed |
| `p` | `prev_feed` | 上一个 feed |
| `F` | `toggle_fullscreen` | 切换全屏/inline |
| `m` | `mark_read` | 标记当前文章为已读 |
| `A` | `add_feed` | 添加 feed |
| `R` | `remove_feed` | 移除当前 feed |
| `g` | `refresh_feed` | 刷新当前 feed |
| `i` | `import_opml` | 导入 OPML |
| `o` | `export_opml` | 导出 OPML |
